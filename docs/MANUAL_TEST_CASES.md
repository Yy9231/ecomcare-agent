# EcomCare Agent 手工测试用例

本文档用于验证客户系统、客服工作台、登录权限、聊天持久化、Agent 工具、RAG、人工审批与人工回复。共 20 个测试用例。

## 1. 测试环境

- 客户系统：<http://localhost:5173/customer>
- 客服工作台：<http://localhost:5173/agent>
- 后端健康检查：<http://localhost:8000/api/v1/health/ready>
- 客户账号一：`customer1 / customer123`，身份 `CUST-001`
- 客户账号二：`customer2 / customer123`，身份 `CUST-002`
- 客服账号：`agent / agent123`
- `CUST-001` 自有订单：`EC2026080001`
- `CUST-002` 自有订单：`EC2026080002`

建议同时打开客户系统和客服工作台。测试 16～18 会改变审批数据，请按顺序执行，并为申请原因附加当前时间，避免与以前的测试记录混淆。

## 3. 详细用例

### TC-01 客户正确登录

**前置条件**：客户页面处于未登录状态。

**步骤**：

1. 打开客户系统。
2. 输入账号 `customer1`、密码 `customer123`。
3. 点击“登录”。

**预期结果**：

- 进入客户聊天页面。
- 页面显示“当前客户：林晓 · CUST-001”。
- 顶部出现“退出登录”按钮。
- 不出现客服指标、审批或其他客户数据。

### TC-02 客服正确登录

**前置条件**：客服页面处于未登录状态。

**步骤**：

1. 打开客服工作台。
2. 输入账号 `agent`、密码 `agent123`。
3. 点击“登录”。

**预期结果**：

- 进入客服工作台。
- 能看到会话数、自动解决率、工具成功率和平均工具耗时。
- 能看到最近会话、会话详情和风险操作审批区域。
- 顶部出现“退出登录”按钮。

### TC-03 错误密码拦截

**步骤**：

1. 在任一登录页输入正确账号 `customer1`。
2. 输入错误密码 `wrong-password`。
3. 点击“登录”。

**预期结果**：

- 页面提示“用户名或密码错误”。
- 用户仍停留在登录页。
- 不生成有效登录状态。
- 错误信息中不显示密码、Token 或服务器堆栈。

### TC-04 客户账号不能进入客服系统

**步骤**：

1. 退出客服工作台当前账号。
2. 在客服登录页输入 `customer1 / customer123`。
3. 点击“登录”。

**预期结果**：

- 页面提示“该账号没有客服工作台权限”。
- 无法看到指标、全部会话和审批列表。

### TC-05 客服账号不能进入客户系统

**步骤**：

1. 退出客户系统当前账号。
2. 在客户登录页输入 `agent / agent123`。
3. 点击“登录”。

**预期结果**：

- 页面提示“该账号不是客户账号”。
- 无法进入客户聊天页面或创建客户会话。

### TC-06 刷新页面保持登录

**前置条件**：使用 `customer1` 成功登录。

**步骤**：

1. 在客户聊天页面刷新浏览器。
2. 再关闭当前标签页并重新打开客户系统。

**预期结果**：

- 两次操作后都不需要重新输入账号密码。
- 页面仍显示 `林晓 · CUST-001`。
- 已有聊天内容能够重新加载。

### TC-07 退出后重新登录恢复聊天

**前置条件**：使用 `customer1` 登录。

**步骤**：

1. 发送“持久化手工测试 + 当前时间”，例如“持久化手工测试 14:30”。
2. 等待 Agent 回答完成。
3. 点击“退出登录”。
4. 使用 `customer1 / customer123` 重新登录。

**预期结果**：

- 退出后回到客户登录页。
- 重新登录后，步骤 1 的客户消息和 Agent 回答仍在聊天区域。
- 系统优先恢复最近一条有消息的会话，不被空会话覆盖。

### TC-08 两个客户的数据隔离

**步骤**：

1. 使用 `customer1` 发送唯一文本“仅属于 CUST-001 + 当前时间”。
2. 退出客户账号。
3. 使用 `customer2 / customer123` 登录。

**预期结果**：

- 页面身份变为 `CUST-002`。
- `customer2` 看不到步骤 1 的唯一文本。
- `customer2` 只恢复属于自己的历史会话。

### TC-09 查询自有订单

**前置条件**：使用 `customer1` 登录。

**步骤**：发送“查询订单 EC2026080001”。

**预期结果**：

- 状态区出现 Agent 分析或工具调用反馈。
- Agent 返回订单号、商品名称和订单状态。
- 客服工作台选择该会话后，可以看到 `get_order` 工具轨迹且执行成功。

### TC-10 查询物流

**前置条件**：使用 `customer1` 登录。

**步骤**：发送“订单 EC2026080001 的物流到哪了？”。

**预期结果**：

- Agent 返回承运商、运单号和当前物流状态。
- 客服工作台中出现成功的 `get_logistics` 工具轨迹。
- 回答不包含其他客户的订单信息。

### TC-11 缺少订单号时提示补充

**步骤**：发送“帮我查询一下订单”。

**预期结果**：

- Agent 不猜测或编造订单号。
- 回答提示提供 `EC` 开头的订单号。
- 不执行数据库写操作。

### TC-12 越权订单查询拦截

**前置条件**：使用 `customer2` 登录。

**步骤**：发送“查询订单 EC2026080001”。

**预期结果**：

- 系统提示未找到属于当前客户的订单。
- 不返回该订单的商品、金额、物流单号等信息。
- 客服工作台工具轨迹显示查询未成功。

### TC-13 RAG 回答与知识来源

**步骤**：发送“我的 Aurora X1 手机无法开机，应该怎么办？”。

**预期结果**：

- Agent 给出检查电源、线缆或长按电源键等知识库建议。
- 回答下方显示知识来源卡片。
- 来源包含文档标题、路径和版本，例如“商品手册/EC-SKU-001 · v1.0”。
- 客服工作台工具轨迹包含 `search_knowledge`。

### TC-14 退货资格确定性判断

**前置条件**：使用 `customer1` 登录。

**步骤**：发送“订单 EC2026080001 能不能退货？”。

**预期结果**：

- 系统调用 `check_return_eligibility`。
- 返回是否符合条件以及明确原因，例如是否在七天期限内。
- 仅查询资格，不创建售后申请，也不出现待审批操作。

### TC-15 高风险操作进入待审批

**前置条件**：客户与客服页面都已登录。

**步骤**：

1. 客户发送“我要为订单 EC2026080001 申请退货，原因：测试待审批 + 当前时间”。
2. 观察客户页和客服工作台。

**预期结果**：

- 客户页面提示售后操作已暂停并等待客服审批。
- 客户输入框暂时不可再次提交高风险操作。
- 客服工作台“风险操作审批”数量增加，并显示客户、订单和申请原因。
- 此时尚未创建最终售后申请。

### TC-16 客服批准并恢复执行

**前置条件**：TC-15 产生一条待审批操作。

**步骤**：

1. 在客服工作台找到对应审批卡片。
2. 点击“批准并执行”。
3. 等待审批卡片消失或状态刷新。

**预期结果**：

- 待审批数量减少。
- LangGraph 从暂停点恢复执行。
- 系统创建售后申请，并生成售后申请编号。
- 重复刷新页面不会重复创建同一申请。

### TC-17 客户收到审批通过结果

**前置条件**：已完成 TC-16。

**步骤**：保持客户页面打开，等待审批结果自动同步；如果已经关闭，则重新打开并登录。

**预期结果**：

- 客户页面出现明确的“审批通过”结果卡片。
- 页面显示“客服已同意退货申请”。
- 内容包含售后申请编号。
- 重新登录后结果仍然存在。

### TC-18 客服拒绝与客户结果同步

**步骤**：

1. 客户重新提交一条不同原因的申请，例如“申请退货，原因：拒绝流程测试 + 当前时间”。
2. 客服工作台点击对应卡片的“拒绝”。
3. 返回客户页面观察结果。

**预期结果**：

- 客服工作台待审批数量减少。
- 客户页面出现“审批未通过”结果卡片。
- 页面显示客服拒绝结果或备注。
- 不创建新的售后申请。

### TC-19 转人工、常用语和人工回复

**步骤**：

1. 客户发送“我要投诉，请转人工客服”。
2. 客服工作台打开标记为“人工”的对应会话。
3. 确认界面显示“客服常用语”区域。
4. 点击常用语“您好，我是人工客服，已经接手您的问题。”并发送。
5. 再输入一条自定义回复“已为你核实完成 + 当前时间”并发送。

**预期结果**：

- 客户页面状态变为等待人工客服或人工客服在线。
- 客户页面依次收到常用语和自定义回复。
- 人工消息带有“人工客服”标识，与 Agent 消息视觉区分。
- 刷新或重新登录后，两条人工消息仍然存在。

### TC-20 工作台刷新与指标反馈

**前置条件**：客服已登录，且已执行若干聊天和工具测试。

**步骤**：

1. 记录当前会话数和工具成功率。
2. 点击“刷新数据”。
3. 观察按钮状态和指标卡。
4. 刷新整个浏览器页面。

**预期结果**：

- 点击后按钮短暂显示“刷新中…”或旋转反馈，随后显示“已更新”。
- 不出现 `Invalid or expired token`。
- 指标来自当前数据库，刷新页面后数值保持一致。
- 会话列表、审批列表和已选择会话仍可正常加载。

## 5. 验收标准

- 20 个用例全部执行。
- P0 用例必须全部通过。
- 客户越权访问和未审批写操作拦截率必须达到 100%。
- 允许存在不影响主流程的视觉问题，但需要登记缺陷。
- 测试数据和指标必须记录真实结果，不填写虚构数值。
