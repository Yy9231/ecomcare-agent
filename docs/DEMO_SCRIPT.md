# 2–3 分钟面试演示脚本

1. 用 20 秒介绍架构：单 Agent、六类业务能力、确定性服务层和 PostgreSQL checkpoint。
2. 在客户页发送“订单 `EC2026080001` 的物流到哪了”，指出工具状态、订单归属校验和结构化结果。
3. 发送“我要为订单 `EC2026080001` 申请退货，商品不合适”，展示请求暂停而不是直接写数据库。
4. 打开独立的客服工作台 `/agent`，查看工具轨迹并批准操作；说明 LangGraph 使用相同 `thread_id` 恢复。
5. 返回会话详情查看售后编号和审计记录。
6. 客户发送“我要转人工客服，我要投诉”，在客服工作台选择带“人工”标记的会话，点击常用语并发送，展示客户侧实时收到人工回复。
7. 展示评测报告，明确区分离线路由指标与真实模型指标，并介绍下一步如何替换 Embedding、扩充数据集。

建议追问回答：

- 为什么不用多 Agent：当前流程单图足够，多 Agent 会增加成本和不可控路由。
- 如何防止越权：客户身份来自 JWT，不暴露为模型工具参数，SQL 同时过滤订单号与客户 ID。
- 如何防止重复退款：所有写操作使用唯一 `idempotency_key`，数据库有唯一约束。
- 模型宕机怎么办：默认确定性路由仍能完成核心演示；生产环境应增加超时、重试、熔断和告警。
