# EcomCare Agent 核心测试用例

本文档包含 10 个核心手工测试用例，用于快速验证客户系统、客服工作台和 Agent 主链路。

## 测试环境与账号

- 客户端：<http://localhost:5173/customer>
- 客服管理端：<http://localhost:5173/agent>
- 客户账号：`customer1 / customer123`，身份 `林晓（CUST-001）`
- 备用客户账号：`customer2 / customer123`，身份 `陈晨（CUST-002）`
- 客服账号：`agent / agent123`
- `CUST-001` 自有订单：`EC2026080001`
- `CUST-002` 自有订单：`EC2026080002`

状态填写：`通过 / 失败 / 阻塞 / 未执行`。

## 详细测试用例

### TC-01 客户端登录

**前置条件**：客户页面处于未登录状态。

**步骤**：

1. 打开客户端。
2. 输入 `customer1 / customer123`。
3. 点击“登录”。

**预期结果**：

- 成功进入客户聊天页面。
- 页面显示“当前客户：林晓 · CUST-001”。
- 顶部显示“退出登录”。
- 输入错误密码时提示“用户名或密码错误”，且不会进入系统。

### TC-02 客服管理端登录与权限隔离

**步骤**：

1. 使用 `agent / agent123` 登录客服管理端。
2. 确认能够看到指标、最近会话和风险审批区域。
3. 退出后，尝试使用 `customer1 / customer123` 登录客服管理端。

**预期结果**：

- 客服账号可以正常进入工作台。
- 客户账号登录客服管理端时提示没有权限。
- 客户账号无法查看全部客户会话、指标和审批数据。

### TC-03 聊天记录持久化

**前置条件**：使用 `customer1` 登录。

**步骤**：

1. 发送“持久化测试 + 当前时间”，例如“持久化测试 10:30”。
2. 等待 Agent 返回结果。
3. 刷新页面，确认消息仍然存在。
4. 退出登录，再使用相同账号重新登录。

**预期结果**：

- 刷新页面后保持登录并恢复聊天内容。
- 退出后重新登录，客户消息和 Agent 回复仍然存在。
- 系统恢复最近一条有消息的会话，而不是创建空白会话覆盖记录。

### TC-04 客户数据与订单隔离

**步骤**：

1. 使用 `customer1` 发送唯一消息“仅属于林晓 + 当前时间”。
2. 退出并使用 `customer2` 登录。
3. 使用 `customer2` 查询订单 `EC2026080001`。

**预期结果**：

- `customer2` 看不到 `customer1` 的唯一消息。
- 系统提示未找到属于当前客户的 `EC2026080001`。
- 不泄露该订单的商品、金额、物流单号等信息。

### TC-05 订单和物流查询

**前置条件**：使用 `customer1` 登录，同时打开客服管理端。

**步骤**：

1. 发送“查询订单 EC2026080001”。
2. 发送“订单 EC2026080001 的物流到哪了？”。
3. 在客服工作台打开对应会话。

**预期结果**：

- 订单查询返回商品名称和订单状态。
- 物流查询返回承运商、运单号和物流状态。
- 工具轨迹分别出现 `get_order` 和 `get_logistics`，且执行成功。

### TC-06 RAG 知识检索与引用

**步骤**：发送“我的 Aurora X1 手机无法开机，应该怎么办？”。

**预期结果**：

- Agent 返回检查电源、线缆或长按电源键等建议。
- 回答下方显示知识来源卡片。
- 来源包含文档名称、路径和版本。
- 客服工作台工具轨迹包含 `search_knowledge`。

### TC-07 退货资格判断与待审批

**前置条件**：使用 `customer1` 登录，客服管理端保持打开。

**步骤**：

1. 发送“订单 EC2026080001 能不能退货？”。
2. 确认系统只返回资格判断。
3. 再发送“我要为订单 EC2026080001 申请退货，原因：测试申请 + 当前时间”。

**预期结果**：

- 第一次请求调用 `check_return_eligibility`，不创建售后申请。
- 第二次请求暂停执行，客户页面提示等待客服审批。
- 客服管理端出现包含客户、订单和申请原因的待审批卡片。
- 未审批前不创建最终售后申请。

### TC-08 客服批准后恢复执行

**前置条件**：TC-07 已产生待审批操作。

**步骤**：

1. 客服点击“批准并执行”。
2. 返回客户页面等待结果同步。
3. 刷新客户页面或重新登录。

**预期结果**：

- LangGraph 从暂停点恢复执行。
- 系统创建售后申请并返回申请编号。
- 客户页面出现“审批通过”和“客服已同意退货申请”。
- 刷新或重新登录后，审批结果仍然存在。

### TC-09 转人工与客服回复

**步骤**：

1. 客户发送“我要投诉，请转人工客服”。
2. 客服打开标记为“人工”的对应会话。
3. 点击一条客服常用语并发送。
4. 再发送一条自定义回复“已为你核实完成 + 当前时间”。

**预期结果**：

- 客户状态变为等待人工客服或人工客服在线。
- 客户依次收到常用语和自定义回复。
- 人工回复带有“人工客服”标识。
- 刷新或重新登录后，人工回复仍然存在。

### TC-10 最近会话排序与未读数字

**前置条件**：客户和客服均已登录，客服先打开对应会话清除未读。

**步骤**：

1. 客户发送第一条新消息。
2. 等待约 3 秒，观察客服最近会话列表。
3. 客户再发送第二条新消息。
4. 等待约 3 秒，再次观察列表。
5. 客服点击该会话。

**预期结果**：

- 有新消息的会话按最后消息时间自动置顶。
- 第一条未读消息到达后显示红色数字 `1`。
- 第二条未读消息到达后显示红色数字 `2`。
- 列表显示客户姓名“林晓”，下方保留 `CUST-001` 和最后消息时间。
- 客服点击会话后，未读数字消失；刷新页面后不会重新出现。

- 10 个用例全部执行。
- P0 用例必须全部通过。

- 测试结果填写真实数据，不填写未经执行的结果。
